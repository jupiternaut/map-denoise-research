# Windows / WSL2 RTX 5080 移植任务边界

## 唯一任务

以此目录 `TASK.md` 为实施任务，完成固定 V28 CPU 方法的工具化与 GPU 光度评分后端。研究算法和模型保持不变。旧结论是背景，不是要求你再寻找能赢的新滤波器。

先读 README、TASK、ARCHITECTURE、PORTING_NOTES、ACCEPTANCE；原始实验说明放在 reference，只作证据。不要浏览其他本地项目或继承无关线程指令。

## 对象与权限

- 先确认 Windows hostname、当前路径、WSL 发行版/版本、GPU 名称/UUID、驱动、Git commit，写 ENVIRONMENT.json。在 Windows 同机 WSL2 开发属于本任务；不能静默改用远程 Ubuntu/另一张卡，再声称 5080 成功。
- `reference/` 只读。新工程写入经确认的独立目录，不覆盖已有目录。当前目录在 Windows 时，可将交接包复制到同机 WSL 独立目录，但记录两端路径、校验哈希；不移动或删掉原件。
- 允许项目内虚拟环境、官方依赖安装、生成测试夹具、实现和运行验收；不全局升级 Python/驱动、不安装 WSL、不 reboot、不修改防火墙、不杀其他任务、不占用忙碌 GPU。
- 系统安装、驱动升级、超过 500 MiB 的数据下载、公开服务、GitHub push 需用户另行确认。已授权的依赖安装不受数据下载上限约束，但应先展示预计环境大小。
- GitHub 固定提交可只读获取。不要更新到 main 后把不同算法当作同一参考。
- joblib 只加载本包来源且哈希匹配的模型；任意用户模型不自动可信。

## 自主实施

- 实施 M0–M5；阶段验证通过后继续，不每一步等用户批准。只有需要新权限/关键材料时请求输入。CPU 可独立进行的工作继续，不因 GPU 暂忙而停掉全部工程。
- GPU 默认等待空闲：优先读 Windows nvidia-smi 与 WSL 状态，连续三次采样，默认间隔 5 秒、利用率 <10%、可用显存 >=4 GiB，外部计算任务不可见/无法确定时标 UNKNOWN，不能当空闲。阈值只是调度约定，不是硬隔离保证；记录实际状态。
- 显卡忙时不强占、不清理他人显存。在分块边界检查取消/新占用；默认等待最长 20 分钟，仍忙则交付 CPU/代码/可恢复检查点，GPU 阶段标 WAITING_GPU。用户另有空闲策略时遵从用户。
- 相同失败不得只重复命令。最多三次有区别的诊断后写出最小复现、原因和下一步；不要把“短工具名错误”当万能解释，先发现真实可调用工具及参数。
- 不以消耗时间/token 数为成果；不凭空长跑。允许做有用的性能实验，但各实验必须有比较对象、计时范围及结束条件。

## 算法与证据

- 不训练新模型、不改主臂、阈值、法向/支持族、采样、偏移范围、特征顺序、相机或单位。允许工程拆分，但 CPU 参考必须独立保存。
- 不把 GT 传入候选构造/selector；评估器独立运行。不用真实标签选择 GPU 精度/配置来制造精度收益。
- 不把纯 CPU 回退说成 CUDA 通过，不把部分评分加速说成全流程都在 GPU。
- 版本依赖缺失时记录，不能换 sklearn 版本/重训模型后沿用旧模型身份。允许在单独环境试兼容性，必须报告为不同配置。
- 禁止通过改 golden、删失败样本或放宽容差追求绿灯。浮点误差大可改实现；若确需改变契约，要停在变更提案而不是宣称等价。
- 错误值/NaN/分块末尾/无有效候选/近零增益/同分规则均需测试。结果同时记录匹配与不匹配。
