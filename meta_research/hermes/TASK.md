# 单次任务：寻找能迁移的主动诊断与构造方法

## 启动方式

将本目录作为专用任务工作目录；给 Agent 的启动消息：

> 完整阅读 `AGENTS.md` 和 `TASK.md`，按其范围执行。研究对象是科研中的下一步实验与构造决策，不是点云算法本身。先用两句话说明目标、首个可验证动作，然后自主完成规定交付，不修改主工程。

若客户端不自动加载 `AGENTS.md`，将它与本文件一起显式附加，并确认 Agent 已读取；不能假定文件存在就自动生效。这里不安装或配置新的 Agent runtime。

## 目的与非目的

目的：当表示、求解、输出或评价可能失配时，从其他领域借来一个可执行方法，帮助选择最有用的下一次检查或构造。

非目的：给 V1–V24 定罪、证明点云 NP-complete、证明停止永远最好、重新写导师简报、为主工程增设强制门禁。

主动模型诊断、元推理、实验设计、CEGIS/CEGAR 都是候选。可选一个有理由的替代框架；交付是机制及其检验，不是术语综述。数学等价不是强制结论：允许得到受限实例化或反例。

## 要完成的工作

1. 提出一个推荐方法，对至多两个近邻方法说明区别。定义隐藏原因、可选行动、观测、固定外部目的、成本，以及还未掌握的量。
2. 写出映射及其证据强度。若声称价值保持，说明历史分布和收益怎样对应；不能把子问题的命中集等价扩成整个科研流程等价。
3. 实现小参照环境与可计算的策略。有限模型中可以采用成功必然的修复作简化，但须标出其作用，并检查改变该假设的影响。
4. 必须包含解析或穷举可核验的案例：无有益行动而停止；观测可改变后续选择而先查后修；已有充分证据而直接修复。案例用于检验能力，不是证明任何策略普遍获胜。
5. 用相同可用信息与清楚的资源约束，对比固定/简单启发式、信息导向方法、推荐方法和小实例求解参照。报告成本、最终效用、实际动作和解的误差范围。
6. 至少检查测试成本、修复成功率、观测可靠性变化对决策的影响，允许推荐方法输。模型之外的新原因至少用一个反例指出，不要求实现通用发现系统。
7. 最后才将方法映射回 V19、V20、V24：哪些观察能区分哪些解释、会建议什么实验、目前缺什么。此轮只作事后迁移假说，不计算或宣称真实工程后验。

## 最小验收与输出

- `outputs/METHOD.md`：一个推荐机制、数学/算法表达、原始来源、为何可能迁移、未解决部分。
- `outputs/instance.py` 及测试、`outputs/RESULTS.json`：可运行小实例，参数的 `ASSUMED` / 实测来源标签，策略输出与正确性检查。
- `outputs/TRANSFER.md`：一页迁移方案，最多一个建议在主工程验证的动作。允许讨论替换表示或联合模块，但不实施、不下停题命令。
- `outputs/RUN.md`：实际命令、解释器/环境、耗时范围、已完成/失败/未执行。没有执行就不写通过。

如果已在有限实例完成比较却没有迁移优势，交付该结果即可；如果外部依赖阻塞，保留完成项和具体缺口。不得用换主终点、放宽事实标准或增加流程门禁来制造成功。

## 判断成功的标准

不是“说服我们少做实验”，而是：有没有一个比原来更好的、可检验的方式，决定下一步查什么或改什么；其价值在哪些条件下成立，哪些条件下失效。
