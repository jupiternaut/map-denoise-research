最新 E1 的主结果（深度 MAE，mm；每格 36 个图像世界）：

| 输入 | KEEP | full9 + 原决策 P | 图像动态混合 ED + 原决策 P |
|---|---:|---:|---:|
| −60 mm | 60 | **10** | 56.67 |
| 正确输入 | 0 | **0** | 6.67 |
| +60 mm | 60 | **10** | 56.67 |

ED 每个偏移方向改善 2/36，正确输入伤害 4/36。原始 ED 曲线在 30 个有信息世界将正确候选排第一；6 个同色世界平坦。其中只有 30 个不同图像张量，30 个有信息世界也只含 27 个不同张量。真实深度固定 600 mm；这是开发机制试验，不是跨深度或真实场景确认。

最明确的机制是：24 个边界世界无法在窄前景取满四个尺度标定块，全部被准入拒绝；另有正确候选损失最低，但把低损失区压成均匀区间后，区间均值把正确点推到错误候选。不能把“原始排序正确”写成“完整修复成功”，也不能把其直接最小残差诊断追平 full9 写成新算法已胜出。

## 如何核验

在仓库根目录运行：

```bash
python publication/verify_mixed_pixel_20261008.py
python publication/verify_mixed_pixel_20261008.py --arrays
```

第一条只用 Python 标准库，检查归档路径集合、SHA-256 和主表算术；第二条需要 NumPy，追加输入重复、曲线及关键决策证据核验。核验器不导入原算法，也不依赖本机 `/srv` 目录，不重新拟合或生成实验。

历史程序与 JSON 内的绝对路径保留为来源证据。**文件可下载、结果可核算，不等于所有历史 runner 已移植成 Windows 一键执行包**；完整重跑仍需依赖与路径适配。不要通过覆盖源目录来重跑。

本次发布前另核对来源哈希、暂存文件集合和 Git blob 字节，并扫描新增文本中的凭据模式。归档验证与科学结论分开：既有 28 项测试、11,307 项审计检查通过，是原运行的证据，不是本轮又做了 11,307 次科学实验。
