# Predictor v1: frozen image rectangle and texture interpolation

Implementation target: liekkas, this run directory. Main APIs are `estimate_aux(ref, train, ref_cam, train_cam, params)` and `predict_curve(aux, ref_cam, eval_cam, eval_image, grid, incumbent, params, mode)`. No renderer, historical run, scoring image, source ID, scene label, candidate list, true depth, seed, or phase enters `estimate_aux`. `params` is public protocol configuration, never truth-derived per-scene settings. The caller performs the two folds; each fold estimates independently from reference and that fold's training source.

## Chosen method before E1 evaluation

One hypothesis family is fixed: a query-connected opaque oriented rectangle over a background, or one full texture plane. It assumes the queried center belongs to the target. It cannot represent multiple targets, holes, a target behind a nonconstant unestimated background, arbitrary silhouettes, or different exposure. This localization/shape assumption is explicit; no fixture geometry or target dimensions are imported. The prototype is not a general segmentation method. E2 ellipses would be represented approximately by its one fitted rectangle, without selecting a new shape model.

Reference query defaults to (64,64). A clipped square patch has radius20. The background initialization ring is the part with Chebyshev radius12 through20; these are fixed sensor-coordinate sizes. Foreground initialization is the median of the five-pixel center cross; background initialization is the ring median. A two-layer initialization requires absolute endpoint difference greater than max(5 gray, 3 × 1.4826 × ring MAD). Otherwise the method selects a single sampled texture plane. In particular a constant equal-color image becomes a constant single plane and provides no depth discrimination.

The endpoint mixture fraction is clipped to [0,1] and used only once for initialization. The component of fraction>=0.5 containing the query supplies its half-level contour, interpolated on neighboring integer pixel pairs. The component must contain at least4 pixels and not reach the local patch border. Its PCA axes and contour extrema define one four-vertex rectangle; the rectangle is then frozen. This estimates a rasterized contour approximately and does not claim exact recovery of subpixel footprint geometry.

Foreground donors are integer pixels whose four pixel corners fall inside that fixed rectangle. Background donors lie outside one pixel dilation of the initialized component. There must be >=3 foreground and >=8 background donors. Appearance fields are fixed, reference-resolution, piecewise linear Delaunay interpolation on their respective reference donors, with nearest donor extrapolation outside the donor convex hull. Collinear donors use the same nearest rule. Both full arrays have the image's shape. Scoring subsequently samples these frozen arrays with order1 interpolation and nearest image-border extrapolation. All accepted reference donor intensities are retained; there is no candidate refit, scoring-image appearance fit, exposure fit, or candidate-dependent erosion. The single-plane field uses all local reference patch pixels as donors.

Implementation design correction made before any E1 observation or result was opened: the initially proposed alpha-value donor thresholds were replaced by these spatial donor rules, because using brightness to choose texture donors biases each reconstructed layer's radiance. This was an analytical correction, not an evaluation-driven model selection.

## Background geometry

The reference outer ring is matched to the training image by zero-mean normalized cross correlation over public optical depths300:2:1000 (or an explicitly locked public background_grid). Every depth uses the same ring pixels valid under all scanned projections, at least32. NCC>=0.2 is required. The best NCC grid depth is frozen and its score/support are saved. There is no fixed900 or other world-depth answer in this module.

If outer-ring standard deviation is below1 gray, background depth is unidentifiable. The declared conditional geometry is a constant background behind all finite target hypotheses: `background_geometry='constant_background'`, `background_depth=inf`, `background_depth_valid=False`. Infinity is a geometry convention, not an estimated depth. NPZ may preserve inf; summaries should use JSON null plus the geometry flag. The background is still represented by its fixed reference donor field; tiny fluctuations below this threshold are treated as negligible for estimating its geometry. A textured ring with insufficient NCC/support makes auxiliaries unavailable; it is not replaced with a historical depth. This baseline foreground/background model also assumes a spatially separated query target and uncontaminated outer ring.

## Scale and raw information

Sigma uses reference donor residuals from the training inputs, with no scoring pixels. Each surface is independently validated on a fixed integer-coordinate lattice: held2×2 blocks, an additional2-pixel guard on every side, and stride6 between held blocks, so guard tiles do not overlap. At least3 donor pixels are needed in a held block, and at least8 donors must remain outside its guard. The frozen interpolation rule is fit only to the remaining donors to predict the held block. At least4 usable blocks and12 held pixels are required on every active surface. The residuals from active surfaces are pooled; sigma=max(1,1.4826×MAD). Held reconstruction is solely scale estimation, never a candidate-specific appearance fit.

Thin layers may fail that explicitly conservative spatial sample requirement. Then `valid=True` can coexist with `sigma_valid=False`, sigma=NaN, and raw curves remain available. The runner must not treat a missing scale as loss absence. The parent protocol combines the two E fold scales by pixel-count-weighted variance and applies that identical scale to EF/ED/OF/OD; missing either E fold scale prevents P-endpoint support for all four but does not delete raw oracle curves.

## Forward prediction and fixed coverage

Each evaluation pixel has nine equally weighted rays at offsets {-1/3,0,1/3}². Rays are transformed by supplied camera K,R,C and intersect planes of constant reference optical Z. Foreground and background reference-coordinate fields are sampled along their own ray intersections. Polygon membership determines target coverage. For finite estimated background geometry the nearer plane wins; equal-depth ties belong to background. The single-plane mode has all target ownership. Out-of-domain appearance always uses the same frozen nearest extrapolation and is never silently removed.

Dynamic mode recomputes each ray's ownership and depth ordering at each candidate. Fixed mode computes those booleans at the supplied incumbent, then uses those same per-ray booleans across the scan, while recomputing candidate foreground texture coordinates. The background warp is shared by the arms. Fixed mode does not freeze the texture warp and is not a stop-gradient approximation.

The common scoring ROI depends only on public reference window (default3×3 integer centers plus half-pixel footprint), complete public scan grid, supplied cameras, and image bounds. Projected corner positions over the grid form a bounding rectangle; all integer evaluation pixels whose sensor squares intersect it are used. This rectangle includes any gaps in the projection union, consistently for all arms/candidates. The ROI never depends on estimated boundary, incumbent, candidate coverage, or observed intensity. One invalid projected ray or unavailable auxiliary invalidates the complete comparison; no depth-dependent subset means are computed. All valid losses are unweighted mean squared error over raw integer evaluation pixels; the caller combines folds by pixel count.

## API details and resource bounds

`predict_pixels(...)` takes the same arguments as `predict_curve` except eval_image is omitted. It returns prediction(D,N), alpha(D,N), ownership bool(D,N,9), roi int(N,2) in x,y order, and depth_valid bool(D). `sensor_roi` and `project_reference_pixels` support independent E0 checks. `predict_curve` returns loss(D), sigma, sigma_valid, valid, reason, pixel_count, roi, flat, auxiliary_valid, and scale_reason. Oracle auxiliaries use these exact prediction functions; a missing oracle sigma does not prevent raw prediction. `mode` accepts NumPy zero-dimensional unicode strings.

Predictions are vectorized over a local fixed ROI and depth batches of64, with no whole-image per-depth traversal. KD-tree query has workers=1. The process caller must keep BLAS threads=1 and total workers<=2. Tests use only hand-built arrays and analytical parallel-camera transforms, never E1 files. No full E1 or E2 is run by this agent.
