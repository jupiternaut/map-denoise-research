# 长程自主执行：持续产生工件，不持续复述计划

## 一、窗口与承诺

首次实质执行写 SESSION.json：开始时间、约 8 小时目标结束时间、CPU/GPU状态、任务根目录。
这个窗口包括调试和实验。允许正常提前完成；不得为了耗满 TOKEN 反复跑同一负结果。
没有用户新指令，不自动滚动为永不停止的付费/跨机器任务。
用户让继续时，可以从检查点开启下一窗口；不要重置已暴露数据的身份。

## 二、每轮循环

1. 读取 TASK_QUEUE.md 和当前候选状态，选能推进几何成果的一项工作。
2. 用最多五行记录假说：当前错在哪里、改哪个自由度、预计哪个可测结果改变。
3. 实现并保存一个实际新工件；最小技术检查只覆盖此次改动，不先建完备平台。
4. 在小真实 ROI 上测，保存输入、候选、参数、版本、时长、失败。
5. 依据开发证据选择扩大、改构造、与另一路组合或放弃；不能只宣布“值得继续”。
6. 每完成一个阶段推进队列，不等用户逐项说“同意”。

首个真实 ROI 有效前，不花整夜写综述/框架/自动实验调度器。
候选有改动但几何数组完全相同的，先排查无效动作/身份回退，不能计为一个成功新版本。

## 三、利用想象力的方式

- 允许同时保留一个最稳定实现和一个高风险构造；最多两条活跃几何路线，另保留公平基线。
- 初始 plane-sweep/atlas 可以被替换。可改变数学表示，而不只是换阈值。
- 若模块收益被上游错误掩盖，可同时修正上游，再补匹配对照；不永久冻结错误底座。
- 可以用小规模密集搜索、多个初始化或更大支持域找算法潜力；记录实际预算，基线有同等机会。
- 主要改动不应全部局限于同一方法多跑几轮；也不要求为了“大胆”机械凑三个不同方法。
- 开发总评可以启发新假说；不得把 GT 选择、GT 法向或真实间距写成部署算法的隐藏参数。

IDEA_LAB.md 是起点，不是“只许从菜单选”。新提案只要守住输入、输出、目标和权限即可试。

## 四、怎样避免重复折返

每次实验留一行 evidence ledger：
`id / 假说 / 改动 / 输入与候选hash / 主结果 / 控制损伤 / 决策 / 重开条件`。
不必为每一行写长报告。
同一失败只有在换了被怀疑的机制、获得新观测或找到代码错误时才重开。
某路线连续 2 次修改都没有改变关键预测，先更换机制或做一次定向诊断；不是整项任务停机。
不反向调 alpha 来迎合暴露分数，不将新评测阈值定义为旧失败的成功。

## 五、GPU 等待和其他阻塞

GPU_POLICY.md 优先。GPU 忙时 CPU 做：输入校准、参考实现、局部小图块、评价器、真实 ROI分析、源代码集成。
每个外部依赖给一个有限的定位/安装尝试窗口，再进入已授权备用工作。
官方 MVS 未复现不能隐去；继续实现不依赖它的部分，并在最后报告比较缺口。
空间不足只停止新增大工件；保留小规模分析、核验和报告，不清理用户旧资料。

## 六、中断恢复

每 20–30 分钟及每个长任务结束更新 CHECKPOINT.md，至少含：

- 当前阶段和接下来的三项工作；
- 已有候选、封存运行和主要结论；
- 活跃命令的 PID、开始时间、日志、输出位置；
- 输入/依赖是否已准备；
- 最早下一条**已存在程序**的命令；尚需编写的模块明确标 TODO。

恢复时先核对进程是否仍存活以及命令身份。不能只因 PID 相同就认定是同一任务。
若进程完成但主 Agent 没读结果，先验收工件，不重新启动。
若命令退出，只重试失败分片；输出先临时保存再标完成，不能把半个文件当 checkpoint。
宿主中断不能由 Markdown 自行恢复；下次继续提示应足以无歧义接上。

## 七、什么时候可以结束本轮

- 任务队列闭合：已有真实实现、对照、评价、图和可复现交付；即使假说失败也可结束。
- 工作窗口结束：保存阶段交付和待跑命令，明确未完成项。
- 需要新权限/目标不匹配且安全替代工作已耗尽：报告具体阻塞。

不要以“计划完成”“测试都绿”“发生负结果”“GPU 忙”单独结束。
也不要把停止条件改成“必须赢”：结论不能被长程要求绑架。
