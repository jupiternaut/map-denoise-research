# GPU 空闲使用契约

用户明确要求：显卡空闲时再跑 V25 的 GPU 工作。此规则优先于加速和长跑时长目标。

## 启动前

只读查看 `nvidia-smi`，不要杀任何已有进程、卸载已有模型或重置显卡。
以物理 GPU UUID 绑定目标；不是简单认定所有机器的 GPU 0 都是同一张卡。
当前已核验主机 liekkas，设备 RTX 3060 Ti 8 GiB；空闲显存是动态状态，不能照抄准备时数据。

默认空闲判断（实际采样再记录）：

1. 没有其他用户/项目的 CUDA compute 进程；桌面图形进程可保留。
2. GPU 利用率低于 10%，连续三次、间隔约 20 秒。
3. 可用显存至少 `max(4096 MiB, 测得峰值需求 + 1024 MiB)`。
4. 无法确定占用/设备状态时按“不空闲”处理，不试探性申请大张量。

检查失败不妨碍 CPU 任务。每完成一个 CPU 阶段或约 5 分钟再检查一次，
避免忙轮询和不断重复同一句等待消息；单次阻塞等待不超过 60 秒。
会话必须仍在运行；本 Markdown 不是常驻调度服务，不会自行唤醒 Cursor。

## 执行中

- 一个 GPU 重任务；先小批次测峰值，分块处理图像/深度。
- 用本工作区的 advisory lock 防止本项目重复启动；明确它不能排斥外部项目。
- 启动前复查，检查与启动仍存在竞态；不能声称获得了独占 GPU 保证。
- 新外部任务出现或显存不足时，在本任务最近的可恢复批次边界停止新增 GPU 批次，释放自己的资源。
- OOM 保存具体命令/参数；减小批次或用 CPU，不能修改驱动或重启系统。
- 启动命令、PID、UUID、峰值口径、退出状态和实际输出写入运行记录。
- 已有官方 COLMAP 路线若要求 CUDA，不能假装它自动退回 CPU。自研 CPU 对照必须另命名。

## 窗口结束

未获得空闲 GPU：交付 CPU 结果、`GPU_PENDING` 与确切续跑命令。
不为“跑满 8 小时”创建未经请求的系统 cron、守护服务或跨机器任务。
