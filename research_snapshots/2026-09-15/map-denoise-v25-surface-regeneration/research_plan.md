# V25 长程执行计划

状态：已布置，尚未执行算法。默认约 8 小时；这是执行队列，不是必须逐小时等待的日程。
续跑和技术分支见 LONG_RUN.md / TASK_QUEUE.md / IDEA_LAB.md。时间分段是参考，不是必须先完成全部准备才允许构造。

## 准备：方法和能力

方法摘要：局部多视图深度证据产生多个表面候选，面片的形状和有效支持可变，
输出重新采样的几何，并在同观测基线和独立激光评价中检验额外收益。
普通 MVS 的像素级视图选择/几何一致性已有成熟方法；不能把复现包装为原创。

技能映射：map-denoise-research 负责机制/评价分离；general-workflow-planner 负责依赖与计划。
当前没有上游技能专用 Artifact API，本文件是用户授权的本地任务文档，不声称已创建外部 artifact。
代码、重建接口、独立新评价器都需实现；没有某个 Skill 能一键完成 V25。
无需新建 LLM API；Cursor 本身负责开发，不让每次滤波再依赖未授权模型服务。

## 执行阶段与里程碑

### 0. 身份、时钟、环境（目标约 0–30 分钟）

读任务文件并运行 preflight.py；创建 `SESSION.json`，记录 UTC 开始/目标结束、host、工作区和当前阶段。
创建 `runs/<UTC>/`、`src/v25/`、`tests/`、`configs/`、`figures/`，全部在本目录。
锁定实际读取的旧代码/输入依赖哈希，不必扫描哈希整个用户目录。
确认 Python 可复用库、新 `.venv` 需求、GPU_POLICY；不以 GPU 等待阻塞 CPU。
工具失败先核对 schema，最多两次同类盲试；不耗一小时重复相同失败命令。

### 1. 并行工作，尽快有真实点云（目标约 0.5–2 小时）

有可用子 Agent 时：

| 角色 | 文件所有权建议 | 首个产物 |
|---|---|---|
| 观测/基线 | `src/v25/observations.py`、`baselines/` | 相机核验、一个 ROI 的深度/融合输出 |
| V25 构造 | `src/v25/surfaces.py`、`src/v25/regenerate.py` | 分片/变支持的实际几何，不只是流程图 |
| 独立评价 | `evaluation/`、`tests/` | 固定空间 ROI、密度控制、双向指标测试 |

没有子 Agent 时按同接口串行，保持评价代码独立，不谎称多人验收。
共同 `evidence_bundle` 至少包含：scene/ROI/坐标系、像素/视图索引、深度候选、有效性、重投影信息、来源哈希。
其中禁止出现参考点、真实层标签或 GT 最优候选。
普通融合、受限输出和 V25 必须能复用相同 bundle。

先打通一个平面/台阶合成小测+一块真实 ROI；不要等完整算法才写第一份 `.ply`。
COLMAP 定位/独立安装最多约 45 分钟的串行阻塞；可与其他工作并行。
不可用时继续自研 CPU plane-sweep/ZNCC 对照，记录官方基线缺口，不能把 GPU 版 COLMAP 写成 CPU 已跑。

### 2. 首轮真实开发矩阵（目标约 2–4 小时）

冻结首批 8 ROI（两个场景，每场景约 3 结构+1 普通面）及评价采样配置。
运行 identity、官方或明确命名的标准融合、共享证据受限输出、V25。
每个 ROI 一完成即保存候选+代码/配置摘要，不等全部任务完成才落盘。
CPU 先跑，GPU 空闲才运行分块加速分支。相同科学配置记录 CPU/GPU离散选择差异。
独立评分后看：证据准确性、面片解释、输出覆盖分别在哪一步出错。
保留失败图和坏例，不只绘最好的窗户。

### 3. 大胆修改，有限归因（目标约 4–6 小时）

选最有证据的一项瓶颈做 1–3 次机制修改：改匹配、改支持分裂、改曲面参数化皆可。
若该轮已回答问题但还有时间，按 IDEA_LAB.md 选择新的有区别构造；不把“3 次”当作任务停止上限。
不把多种 LOSS 任意相加后拿训练下降当几何胜出。
每次修改保留预测和旧版本结果；开发上可看 GT 总评反馈，但部署规则不能读 GT。
若已有收益，补同点数/采样密度对照与普通面回归。
若基线更好，先查它的证据/支持区别，保留它而非人为削弱其设置。

### 4. 锁定确认或完成实质开发证据（目标约 6–7.25 小时）

开发信号达到可投入水平：封存主候选、参数、输入选择、评价脚本，再跑 1–2 未使用场景的少量局部 ROI。
新数据下载可以早并行准备，但不能提前读取其 GT 成绩进行选择。
如果获取新场景受阻，完成已有真实 ROI 的对照和独立核验，诚实标为开发成果。
如果需要修改已锁定科学构造，回开发并另开确认批次，不在原确认记录覆盖。
若有时间且主比较已闭合，优先完成官方基线，而非另开一个大型模型路线。

### 5. 收尾（最后约 45 分钟）

按 ACCEPTANCE.md 逐项检查。独立实现重算核心几何指标并核对源文件未改。
从真实 CSV 和工件作图并打开检查：固定视角前后、剖面、精度/覆盖、普通面控制、坏例。
写 REPORT.md，列出测得/未测得/失败；COMMANDS.md 提供实际可运行的命令与环境。
更新 CHECKPOINT.md，包含每个 PID 状态、完成/待跑项和最早下一条命令。
不要临睡前留一个不知道是否还在运行的后台任务，也不要写空白“后续优化”。

## 持久化接口（执行 Agent 实现，不是假定已有）

建议做简单 CLI：`prepare` → `evidence` → `regenerate` → `seal` → `evaluate` → `report`。
命令名可自主选择，必须真实可运行后才写 COMMANDS.md。
每例状态至少 QUEUED/RUNNING/SUCCEEDED/FAILED/GPU_PENDING；状态变化带时间与原因。
恢复按工件哈希和状态继续，错误退出不把半写文件当完整输出。
阶段完成可以推进下一阶段，不必用完表中估计时间；不要启动系统级定时服务来维持会话。
