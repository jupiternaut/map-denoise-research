## 一、真正应该记录的状态，不只是“版本号＋数学工具”

我建议把一个研究状态写成：

\[
\boxed{
S_v=(Q_v,I_v,H_v,A_v,D_v,L_v,E_v)
}
\]

这是本次整理采用的描述框架，不是仓库已经实现的状态机。

| 字段 | 要记录什么 | 为什么需要 |
|---|---|---|
| \(Q\)：问题 | 本轮到底想解决什么 | 避免从“去重影”悄悄变成“让表面更平” |
| \(I\)：输入信息 | XYZ、站号、射线、给定 σ、参考数据的权限 | 区分算法变化与新增信息 |
| \(H\)：假设 | 平行面、共享偏差、空间门控、噪声分布 | 知道算法允许什么世界 |
| \(A\)：估计与求解 | 关联、参数拟合、初始化、优化器、候选池 | 区分模型问题与搜索遗漏 |
| \(D\)：输出决策 | MAP、mean、quota、共同位移等 | 同一估计可以产生不同输出 |
| \(L\)：评价 | 表面距离、对应 RMS、间距、覆盖、W1 | 避免换一个指标就宣布成功 |
| \(E\)：证据状态 | 开发、同族确认、反事实、独立参考、撤回 | 知道结论究竟走到了哪一步 |

**状态转移最重要的记录，是“这次改了哪一项，又把哪些项固定住”。**

另外，你所说的“数学分析工具”，在这个项目里已经跨越了几门学科：**线性代数、概率统计、数值优化、计算几何、频谱分析与最优运输**。不宜把它们统称为微积分意义上的“数学分析”。

## 二、V1–V23 状态总表：每一版用什么工具，解决什么问题？

下面保留主问题与主要工具。多支线、输入假设、对照和具体限制，完整写在 Excel 与 Markdown 状态卡里。

### 第一阶段：V1–V6，先处理共同偏差、参数共享与关联

| 版本 | 要解决的问题 | 主要数学工具 | 实验留下的判断 |
|---|---|---|---|
| **V1** | 既有算法能否处理多扫描重影与薄层？ | 既有混合模型、含帧偏差的 fast、点到点 ICP、扰动注入 | 部分坐标、计分和归因有误，后来撤回；不是可靠的初始排名。 |
| **V2** | V1 的失败有多少来自实验契约错误？ | 坐标变换、独立几何评价、当前输入坐标系下复评 | 修复实验可信度，**不是新算法**；共同偏差处理信号仍在，但双层仍可能受损。 |
| **V3** | 如何分离局部真实层差与扫描共同偏差？ | **扫描—表面二部图、规范约束、加权最小二乘与块消元；KL 熵正则运输** | 图端有开发信号；运输增加预算后改善，但不平衡运输未胜过同预算平衡版本。  |
| **V4** | 能否扩大统计支持，又不把不同表面混在一起？ | **相容面聚合、充分统计量相加、条件加权回归、运输热启动** | 新种子中表面 MAE 改善，层距误差略增；保留相容聚合，不称全面保真。 |
| **V5** | 进一步共享斜率，能否缓解薄层收缩？ | 分组仿射回归、共享斜率、节点截距、SVD 核查 | 双层整体退化；混合组产生的斜坡被共享到其他组。不是简单秩亏。 |
| **V6** | 共享失败是关联问题，还是方向与支持问题？ | **关联×共享的 2×2 反事实、真标签拆组、PCA、正交投影误差下界** | 正确拆组后共享有益；仅修方向仍可能零支持。得到机制证据，没有得到可部署的新方法。 |

**这一段的主线不是“不断增加曲面复杂度”，而是：哪些点可以共同估计一个几何量？共享何时有益，何时传播错误？**

### 第二阶段：V7–V13，重关联、选择偏差、频谱与局部几何

| 版本 | 要解决的问题 | 主要数学工具 | 实验留下的判断 |
|---|---|---|---|
| **V7** | 不用真标签，能否通过跨片区重关联改善几何？ | **变分 EM、softmax 责任度、加权最小二乘、硬重拟合／直接面投影消融** | 内部目标改善，几何反而变差；首次明确检验“估计与最终动作分开”。 |
| **V8** | 分组引入的条件噪声均值，能否被扣除？ | **截断正态积分、条件期望补偿、固定组回归** | 减轻 V7 损伤，但仍未胜原保留模型，双层间距指标全部恶化。 |
| **V9** | 为什么精确消噪后仍可能缩层？ | **条件期望反例、两折后级交叉拟合、联合条件矩解混、最小范数 SVD** | 正确模型也可能因硬组混层而收缩；联合解混修复理想反例，但实际输出仍未胜出。 |

| **V12** | 缩小窗口，能否避免整片区错拟合？ | **kNN 窗口、Voronoi 核心、局部 PCA、官方 APSS／RIMLS** | 固定窗口版总体变差；正式接入外部对照，也查明真实注入恢复主要来自上游纠偏。 |
| **V13** | 能否“大范围识别关联，小范围拟合几何”？ | **局部表面图册、加权 PCA、方向共享、局部后验修正；解析曲面距离** | 缓解窗口版退化，强曲面条件有益；平板、曲面和真实注入中没有统一胜者。 |

**这一段最重要的不是换了多少数学，而是逐渐分开了三件事：关联是否正确、表面参数是否准确、最终点该放在哪里。**

V20 已经进行了限定范围的诊断，不能再把它当作从未回答的问题。更大的模型族或其他求解状态是否还有空间，是另一项命题。

## 三、为什么不能只画成 `V1 → V2 → … → V23`？

因为至少存在三种性质完全不同的连接。

### 1. 新构造被否定，但旧算子被保留

例如：

```text
V4：相容面聚合
  │
  └─ V5：进一步共享斜率
         │
         └─ 双层退化，不升级，仍保留 V4
```

**算法选择可以保持不变，研究知识却已经改变。**

可以写成：

\[
A_{\text{保留},5}=A_4,
\qquad
E_5\neq E_4.
\]

因此，这不是“研究回到原点”。但也不能把知识增加说成算法精度增加。V5 明确保留了 V4，同时记录了共享斜率在混合组上的具体失败。

### 2. 同一个问题被回访，但实现和控制条件不同

```text
V9：两折后级交叉拟合
             ⇢
V19：三折门控交叉拟合
             ↓
V20：补回各折的强候选链
```

这不是三次完全相同的试验，也不是三条互不相关的新思想。

矩阵必须同时记录：

**共同问题是什么；后一次究竟新增了哪项检验；哪些旧限制仍未消除。**V9、V19、V20 都明确保留了“并非全流程独立”的限制，而 V20 又实测修复了 V19 的候选继承退化。 

### 3. 换了输入与任务，不再是同一张试卷

```text
受控薄板估计
    ↓
一般成品网格的局部点样本
    ↓
独立参考下的距离、召回与完整性评价
```

V21 的输入已不是具有完整扫描来源的原始薄板观测，而是成品重建的局部顶点样本。因此，V18 在合成族上的收益与 V21 的直接迁移失败，需要同时保留，不能互相替代。

**矩阵中“迁移”应该是一种单独的边，而不是默认叫“升级”。**

我在文件中登记了 **39 条关系边**，分别标记“构造、修复、诊断、验证、决策、迁移、复用、保留、回访、建议”。这些是关系标签，**不是转移概率**。

## 四、这张矩阵已经揭示了五条值得利用的研究记忆

### 1. “估计与动作分离”并不是 V18 才出现

V7 已经比较硬重拟合与直接使用 soft-M 表面；V9 已经给出条件 MSE 最优与层间距真实不一致的反例；V18 才把同一拟合下的 MAP、half、mean 对照做得更明确。  

**下一次讨论输出决策，应当继承这条证据链，而不是重新从“软平均也许更好”开始。**

### 2. “丢掉旧好解”是一个重复出现的工程问题

V18 修复了 V17 的旧空间候选遗漏，V20 又修复了 V19 的候选链继承。它们不是同一个缺陷，但属于同一类接口风险。 

因此，需要长期保留的规则不是“每版都多加一些初值”，而是：

> **新求解器必须明确说明，旧可行候选如何进入同一目标、同一约束下的比较。**

这条规则约束实现，不保证科学结果一定改善。

### 3. “局部化”被尝试过，但不是一个单一旋钮

V12 同时改了窗口和法向；V13 分开大范围关联与局部几何；V22 又变成逐点 MLS，并改变了输入表示、噪声处理与动作。  

所以，“小窗口好不好”“二次面好不好”都过于粗糙。

真正有用的转移描述应是：

> **关联上下文不变，只缩小几何拟合支持。**

或者：

> **邻域不变，只改变局部多项式次数。**

不能隔离时，就明确记录同时变化的因素，不强行认领单一原因。

### 4. 工具已经不少，缺的是“工具负责什么”的稳定边界

V3 的运输主要提供扫描纠偏关联；V10 的频谱提供层距线索；V19 的后验测度提供分布导出。它们不能因为都涉及概率或测度，就被当成同一个任务上的替代算法。  

从矩阵看，你们真正反复研究的是：

\[
\boxed{
\text{什么信息支持关联}
\;\rightarrow\;
\text{什么参数值得共享}
\;\rightarrow\;
\text{什么输出符合任务}
}
\]

**这比“下一版应该学哪一种更高级数学”更接近项目的主线。**

### 5. V22 没有证明“已经撞到信息墙”

这一点也需要修正我上一轮的表述。

V22 证明的是：**当前构造在当前测试中，没有把多尺度阻尼转化成胜过简单同位移对照的明确增益。**它没有证明所有只用 XYZ 的方法都无法改善。

同一份信息可能被更好的模型或算法更有效地利用。反过来，一个预测器没有找出收益信号，也不能证明信号不存在。

所以，V23 即使执行了，也应该写成**收益可预测性诊断**，不能仅因预测失败就升级成“不可辨识性定理”。

## 五、以后每个新版本，都只需要补一张“转移卡”

不必增加一套庞大流程。我建议下一版开始前，只填下面六项：

| 字段 | 应当写成什么 |
|---|---|
| **继承哪个状态** | 明确的算子、输入协议、候选池和检查点 |
| **哪个问题仍未回答** | 不能是 V20 已完成的候选余量诊断等旧待办 |
| **这次改变什么** | 观测、假设、关联、求解、选模、动作或评价 |
| **哪些条件保持不变** | 用于区分“方法改变”与“换了一道题” |
| **哪个对照能否定押注** | 旧默认、identity、简单匹配对照；oracle 单列 |
| **不同结果走向哪里** | 升级、保留为专用组件、回到旧参考、停止该分支 |

**这样，“新版本”就不再只是一个新目录，而是一条可解释的状态转移。**

最有价值的也不是把二十三个方框连接起来，而是让每条箭头都回答：

> **我们因为哪条证据，改变了哪一个判断？这次增加的是可用能力、实现可靠性，还是对失败边界的认识？**

把这三种进展分开，你们就能既不抹掉有效结果，也不被版本数量制造的进步感带着走。
