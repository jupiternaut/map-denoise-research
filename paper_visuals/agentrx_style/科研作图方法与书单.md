# 科研作图方法：从研究证据到可复现的论文图版

日期：2026-09-13。本文记录这次 map-denoise-research 四类图的实际制作方法，并提炼成后续项目可复用的流程。

案例版本：GitHub `jupiternaut/map-denoise-research`，提交 `a7b362e8f0e9f77a7861d202145df9bd482e9856`。研究内容为 V22 局部曲面重建与多尺度连续阻尼；参考 AgentRx 的视觉组织方式。方法说明不改变原实验，也不把重绘当作新增实验。

入口：[四页图集](map-denoise-visual-atlas.pdf) · [成品与复现说明](README.md)

## 1. 整体分工

先确定一张图要回答的问题，再决定用哪种图和工具。整体链路为：

```text
固定项目版本与证据
        ↓
核对指标、方法接口、样本单位
        ↓
为每张图写清问题、内容、单位、输出尺寸
        ↓
统一字体、颜色、线宽、标记与留白
        ↓
TikZ 流程图 / Matplotlib 数据图 / LaTeX 表格与代码
        ↓
独立矢量 PDF + SVG + PNG 预览
        ↓
论文用 includegraphics 插图；图集用 PyMuPDF 组合 PDF
        ↓
数值核对 + 实际尺寸读图 + 源文件与命令交付
```

| 内容 | 本次实际使用 | 负责的工作 |
|---|---|---|
| 流程与原理图 | TikZ、Tectonic | 节点、箭头、公式、接口示意、分区 |
| 多面板数据图 | Python、NumPy、Matplotlib | 读记录、计算配对变化、分面、图例与坐标 |
| 三线表 | LaTeX `booktabs`、`tabular*` | 文字、数值、水平线与列间距 |
| Python代码 | LaTeX `listings` | 等宽字体、语法配色、自动换行 |
| JSON代码 | LaTeX `fvextra` / `VerbatimInput` | 原文排版、边框、长行处理 |
| 汇编与检查 | PyMuPDF、Pillow | 矢量页面组合、字体子集化、预览与结构检查 |
| 工作流程 | `data-analytics:visualize-data` Skill | 提醒核对图型、粒度、颜色编码与成品可读性 |

Tectonic 是本次使用的 TeX 编译程序。TikZ 是绘图语言；Matplotlib 是绘图库；LaTeX 宏包负责排版。Skill 则是工作规程，帮助选择和正确调用这些工具。

## 2. 先建立图和证据的对应关系

开始时发现电脑上的旧同名目录与用户指定 GitHub 仓库内容不同，因此另行克隆了给定仓库。在独立目录新增图件，保留旧稿和旧实验记录。

每张图先回答五个问题：

1. 读者看完应该理解什么？
2. 图中的节点、数字和代码分别来自哪里？
3. 一条记录究竟代表点、片区、场景还是一次运行？
4. 使用什么对照、单位和聚合方式？
5. 哪些内容是示意，哪些是已保存结果？

本案例的四图分工：

| 图 | 要回答的问题 | 主要证据 |
|---|---|---|
| 图1 | V22 如何从输入点计算修正？ | `operator.py`、协议与运行脚本 |
| 图2 | 修正对不同片区和不同指标有什么影响？ | 24片区×9方法的216条确认记录 |
| 图3 | 九种方法的精确数值如何比较？ | 同一批记录按片区等权重算 |
| 图4 | 关键公式在真实代码里如何实现，实验判断是什么？ | 源码119–138行及已发布比较JSON |

数据来自一个新确认场景。24个片区不能写成24个独立场景；输入每片区1024点，也不能假定每项指标都评分了1024点。MAE实际使用固定观测区域内的点。

哈希、版本和选取范围保存在 [PROVENANCE.json](PROVENANCE.json)。哈希用于识别字节版本，不能独自证明数据正确；还需检查指标定义和统计过程。

## 3. 先定最终尺寸，再设计细节

本次四张独立PDF的宽度统一为约170mm。170mm是本案例的双栏图设计尺寸；换期刊时，应按目标模板的实际栏宽重新设置。

| 项目 | 本次设置 |
|---|---|
| 背景 | 白色 |
| 正文与图表字体 | Times New Roman |
| 代码字体 | Consolas |
| 图集中文说明 | SimSun |
| 主候选 | 蓝色 `#3778A8`，实心圆 |
| 同位移对照 | 橙色 `#CB7736`，空心方块 |
| 其他方法/辅助结构 | 中性灰、空心标记、细线 |
| 图内字号 | 按用途主要约8–11pt；标题略大 |
| 输出 | PDF正式插图、SVG编辑交换、PNG预览 |

颜色表达类别，标记形状提供第二条识别线索。避免让读者只能靠蓝橙色判断方法。线宽按主线、辅助线、边框三种用途分级。

尺寸与字号一起设计：先画一张巨大图，再缩到单栏，通常会把标签和代码压得难以阅读。空间不足时，优先重排布局、换行或跨栏。

独立分享的图可以自带标题和说明；插入正式论文时，可将重复标题、来源说明移入统一图注。Wilke对这两种使用场景有专门讨论：[图标题、图注与表格](https://clauswilke.com/dataviz/figure-titles-captions.html)。

## 4. 流程图：先画数据流，再添加文字与代码

本次图1的内容顺序是：

```text
点坐标输入 → 排除查询点自身的近邻
                       ↓
               k32 / k64 / k128
               各自PCA与二次拟合
                       ↓
           修正投影至k64法向并融合
                       ↓
                 连续启发式阻尼
                       ↓
                 沿局部法向更新
                       ↓
             输出封存后进行参考评估
```

实际源码采用连续阻尼，所以图里画连续系数与更新公式。参考只参与评分，不能用一根方便的箭头把它连进模型输入。诊断支路也应与主数据流区分。

TikZ适合精确控制节点坐标、边框、公式和连线，并直接产生矢量PDF。图1采用物理毫米坐标与独立 `standalone` 文档，外留白单独计入宽度。

教学片段：

```latex
\documentclass[tikz,border=3mm]{standalone}
\usepackage{fontspec}
\setmainfont{Times New Roman}
\usetikzlibrary{positioning,arrows.meta}
\begin{document}
\begin{tikzpicture}[
  node distance=12mm,
  block/.style={draw,rounded corners,align=center,inner sep=3mm},
  flow/.style={-{Latex},thick}
]
\node[block] (input) {Point coordinates};
\node[block,right=of input] (fit) {Local surface fitting};
\draw[flow] (input) -- (fit);
\end{tikzpicture}
\end{document}
```

这是解释接口的简化片段；完整成品源文件是 [fig01_pipeline.tex](fig01_pipeline.tex)。需要手动拖动时，draw.io也可承担这部分工作，但应保留可编辑文件并检查导出字体和线条。

## 5. 数据图：先算清配对变化，再选择视觉表达

本案例不适合把方法版本号连成时间趋势；同片区处理前后的变化更有解释力。因此图2采用配对标记图，灰线连接同一个片区的观测。

计算口径：

```text
片区ΔMAE = 主候选MAE − 同片区identity MAE
片区Δ召回(pp) = 100 × (主候选召回率 − 同片区identity召回率)
方法平均MAE = 24个片区MAE的等权均值
平均相对改善 = 1 − 主候选平均MAE / identity平均MAE
```

最后一项是“均值之比”，不能擅自替换为“每片区改善率的平均值”。召回率的比例差乘100才是百分点；它也不同于相对百分比变化。

四个面板分别呈现逐片区MAE变化、逐片区召回变化、全部九种方法的均值权衡，以及明确标出的局部放大。全景保留Frozen V18，避免为了放大细微差别而删除表现较差的方法。

关键绘图接口如下，变量由数据处理步骤提供：

```python
fig = plt.figure(figsize=(170 / 25.4, 178 / 25.4))

# 灰线连接同一片区的两个方法；不是时间轴。
ax.hlines(patch_id, delta_primary, delta_control,
          color="#A0A0A0", linewidth=0.7)
ax.scatter(delta_primary, patch_id,
           color="#3778A8", marker="o", label="Primary")
ax.scatter(delta_control, patch_id, facecolors="white",
           edgecolors="#CB7736", marker="s", label="Matched damping")

plt.rcParams["pdf.fonttype"] = 42
plt.rcParams["svg.fonttype"] = "none"
fig.savefig("figure.pdf")
fig.savefig("figure.svg")
fig.savefig("figure.png", dpi=350)
```

PDF中的线条与文字不由DPI决定清晰度；DPI主要影响位图部分与PNG预览。SVG保留文字便于编辑，但在另一台机器上仍需要对应字体。PDF嵌入字体后更适合交付。

完整实现和数值验证见 [plot_results.py](plot_results.py)。数据图与表格读取同一来源，避免两套人工抄数。

## 6. 三线表：数值由程序填写，结构由LaTeX排版

三线表直接保留文字和线条。`booktabs` 提供顶部线、表头分隔线与底部线；`tabular*` 在指定总宽度内分配列间空间。

```latex
\usepackage{booktabs}

\begin{tabular}{lrr}
\toprule
Method & MAE (mm) & Recall (\%) \\
\midrule
Identity      & 0.437246 & 92.358 \\
V22 consensus & 0.434631 & 92.025 \\
\bottomrule
\end{tabular}
```

本次先从JSON计算均值，再由Python写入完整九方法LaTeX表格，统一有效数字。主候选用蓝色加粗表示事前选择，不把它标成每列最佳。小数位数不一致的表格可进一步用 `siunitx` 实现小数点对齐。

不要用极小行距硬塞长表头。可将单位放第二行、缩短方法显示名、增加宽度或拆成合理的两张表。正式名称与显示名称的映射应保存在脚本里。

本次表格源文件由 [build_artifacts.py](build_artifacts.py) 自动生成；修改该生成器后重建，避免只改下一次会被覆盖的 `fig03_table.tex`。

## 7. 代码块：提取原文，换行只影响显示

本次Python代码直接提取项目源码第119–138行，并保存到单独文件。JSON则从已发布 `SUMMARY.json` 的指定层级读取。两者都做原文一致性检查。

代码排版有两层职责：

- `listings` 为Python设置等宽字体、关键词、字符串、注释颜色和续行箭头。
- `fvextra` 的 `VerbatimInput` 排版JSON，保留缩进并处理长行。

```latex
\usepackage{listings}
\lstset{
  language=Python,
  basicstyle=\ttfamily\small,
  breaklines=true,
  breakatwhitespace=true,
  columns=fullflexible,
  keepspaces=true,
  showstringspaces=false,
  frame=single
}
\lstinputlisting{data/operator_excerpt.py}
```

`minted`也可提供基于语法分析器的高亮，本次实际成品使用的是 `listings` 和 `fvextra`。截图式代码图片会丢失可选择文字和可复现排版，优先保存原文代码与排版源。

显示续行箭头不是源码字符。需要读者复制运行时，同时提供原始代码文件；如对长行做手工改写，应标“整理后的等价片段”，不能仍称逐字摘录。

## 8. 如何进入论文PDF

### 外部图形插入论文

流程图和数据图先成为独立PDF，再通过 `graphicx` 插入正文：

```latex
\usepackage{graphicx}

\begin{figure*}[t]
  \centering
  \includegraphics[width=\textwidth]{fig02_confirmation.pdf}
  \caption{Scan37确认片区的误差与覆盖权衡。}
  \label{fig:scan37}
\end{figure*}
```

双栏论文中的 `figure*` 用于跨栏；单栏图用 `figure` 和 `\columnwidth`。插图自身负责坐标轴和图例，正文LaTeX负责图号、图注、交叉引用和页面位置。含中文的上述示例需要论文模板已配置中文支持。

表格、代码块和TikZ也可以直接写入论文源文件，在编译时生成。这里将它们做成独立PDF，是为了方便预览、交换和多处使用。

### 本次四页图集的组合方式

本次图集不是通过截取四张PNG来组合，而是使用PyMuPDF的 `show_pdf_page` 将各独立PDF内容放入新页面，再补中文标题与图注。最后调用 `subset_fonts()`，仅保留用到的字形，缩小中文字体占用；用 `deflate` 压缩PDF对象。

```python
page.show_pdf_page(target_rect, source_pdf, 0)
document.subset_fonts()
document.save("atlas.pdf", garbage=4, deflate=True)
```

PNG由完成后的PDF渲染生成，用于预览和目视检查。这一链路不会把纯矢量图先转成截图。

PDF也能包含照片、点云渲染图等位图。“.pdf”后缀本身不能证明内部为矢量；照片、显微图和大规模点云有时采用位图或混合输出更合理，应按内容和投稿要求选择。

## 10. 检查分三层完成

### 数据与语义

检查是否缺方法、重复片区、混入其他实验阶段，比较是否按同片区配对，均值是否与已发布摘要一致。核对指标单位、方向、分母、样本量以及图注结论。图中每个箭头和判断应有源码或协议依据。

### 文件结构

检查PDF页数、实际物理尺寸、字体、文字越界、缺字、位图嵌入及编译日志。对于这次纯图形/文字输出，0嵌入位图是合适的检查；对含照片的论文，不能把0位图当作通用要求。

### 实际读图

把PDF按最终栏宽渲染，检查图例与标题、箭头和边框、长代码折行、轴边标记、表格留白；再检查组合后的页面。机器检查“没有越页文字”不能证明“没有文字互相重叠”，所以还要目视检查。

本次修复过：数据图极端标记被坐标范围截断、流程图说明压在框边、表格底线与说明间距，以及独立PDF宽度略有差别。

已完成的验证记录包括6个输入来源哈希、36个表格数值交叉核对、20行源码与JSON原文对应、4张独立矢量PDF及4页图集的结构检查。它证明的是制图与已存证据的一致性，不等于重新完成原实验或验证所有研究结论。

## 12. 推荐阅读：实现、数据表达和科研图示三条线

**Jean-luc Doumont。** 范围涵盖科研写作、报告和视觉表达，其中包含图表设计。全书商业出版，作者提供免费的短摘要，适合快速建立选图与改图思路。

官方入口：[作者/出版社书页](https://www.principiae.be/X0100.php)；[免费图表设计摘要PDF](https://www.principiae.be/pdfs/TM%26Th-4.0-summary.pdf)。

### 建议的学习顺序

先用Rougier配合现有Python脚本，解决具体实现；同时用Wilke检查指标和图型；再读Frankel训练流程图与图版组织。LaTeX语法与包参数继续查官方手册，不需要期待一本书覆盖所有工具。

用本项目练习时，可以每次只改变一个设计维度：先改布局，再改字体，再改颜色。保留相同数据和数值检查，比较哪一版让读者更快看懂误差与覆盖的取舍。
